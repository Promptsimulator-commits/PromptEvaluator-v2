- (decision) Feature 1 - criteres d'acceptance: saisie libre par l'utilisateur, un critere par ligne (format texte simple, pas de structure rigide). Formuler les criteres fait partie de l'exercice pedagogique.
- (decision) Feature 1 - formule de score par execution: (criteres valides / total criteres) x 10, generalisee du pattern Prompt Trainer a un nombre de criteres variable.
- (decision) Feature 1 - affichage des resultats: score de chaque execution (les 5) + moyenne globale + detail par critere (nombre de fois valide sur 5) pour reveler l'instabilite d'un prompt, signal pedagogique cle.
- (decision) Feature 1 - le prompt utilisateur est envoye brut au LLM d'execution, sans contexte systeme cache ajoute, pour que le resultat refletance fidelement la qualite du prompt ecrit par l'utilisateur.
- (decision) Feature 2 - analyse porte a la fois sur la structure du prompt (persona/objectif/contraintes/exemples, dimensions de la skill Prompting Produit) ET sur les resultats de la Feature 1 quand ils existent (ex. criteres instables identifies).
- (decision) Feature 2 - disponible avant execution (analyse du prompt seul) ET apres (enrichie des resultats). Format de sortie: structure par les 4 dimensions persona/objectif/contraintes/exemples, chacune evaluee presente/claire/absente avec explication + exemple concret d'amelioration, plutot qu'un prompt reecrit pret a copier-coller.

Les deux fonctionnalites restent accessibles a tout moment sans ordre impose (Julie peut demander l'analyse avant l'evaluation si elle prefere), mais le parcours recommande/mis en avant dans l'UI est evaluation d'abord.
